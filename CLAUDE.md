# GuitarLab: Guitar Practice App (Maturitní práce)

Mobile app for analysing guitar playing and interactive learning: tuner, metronome, Chord Lab, lessons, gamification (XP, streaks, achievements).
School graduation project, October–February. I build it with Claude ("vibecoding"), so I must be able to understand and defend every part of the code. Prefer simple, readable code over clever code.

`AGENTS.md` (imported above) was generated by Expo and holds general Expo guidance. If it conflicts with this file, this file wins.

## Current focus
I don't have an Android phone yet, so I can't test live audio. Build everything that doesn't need the microphone. Screens that need the mic (Tuner, Practice, Results, Input problems, the metronome's "strums vs click" histogram) get their full UI, driven by the mock audio implementation. The working plan is in `docs/plan.md`; follow it and tick off steps as they're done.

## Devices & testing (important constraint)
- **iPhone + Expo Go**: used for UI testing. I have no Mac and no Apple Developer account, so there is NO iOS development build. Everything must load in Expo Go.
- **Android phone + development build** (`expo-dev-client`, EAS `development` profile or `npx expo run:android`): later, for microphone and live audio stream features. An Android Studio emulator is optional for layout checks.
- Any native module that Expo Go doesn't include (live audio / raw PCM stream) must be **isolated and guarded**:
  - Put it behind one interface in `src/audio/` (e.g. `AudioStream` with `start()`, `stop()`, `onFrame(cb)`).
  - Detect Expo Go with `Constants.executionEnvironment === 'storeClient'` (from `expo-constants`) and use a **mock implementation** there (e.g. a fake sine-wave/pitch generator), so the UI still works on the iPhone.
  - Never import the native audio library at the top level of shared screens; load it only inside the real implementation.
- Before adding any library, tell me whether it works in Expo Go, needs a dev build, or needs a config plugin. Install Expo packages with `npx expo install` so versions match the SDK.

## Audio rules
- Pitch detection runs on-device (e.g. YIN / autocorrelation); keep DSP code in `src/audio/dsp/` as pure, testable TypeScript functions.
- Do heavy processing off the render path; throttle UI updates (~20–30 fps is enough for a tuner needle).
- Ask for microphone permission with a clear explanation screen; handle "denied" gracefully.
- Never upload raw audio to Firebase, only results (detected notes, scores, session stats).
- Audio *output* (metronome clicks, chord sounds) must work in Expo Go. Keep the metronome behind a `MetronomeEngine` interface in `src/audio/metronome/` so a more precise dev-build engine can replace it later. Schedule clicks against a monotonic clock; never rely on chained `setInterval` ticks.

## Design & UX
- **Source of truth:** the pen.dev design file `design/guitarlab.pen` in this repo (plain JSON, ~3.9 MB). There is no Pencil MCP: read the raw file with small scripts (`scripts/design/inspect-pen.js`), never load it into context whole. `docs/design-map.md` is the index (screen → frame → route → components). PNG exports, if present, are in `docs/design/screens/`.
- The design brief (`design/guitarlab design/SKILL.md`, note the space in the folder name) and the design rules in `docs/decisions.md` (two visual modes, realism rules, responsiveness, performance) are binding.
- Match the design closely. Never invent screens, flows or copy; if something is unclear, ask.
- All colors, spacing, radii and fonts come from `src/theme/`, named after the `.pen` variables. No hard-coded values in screens.
- **Dark mode only for now** (the design is dark-only), but structure the theme so a light theme can be added later.
- Touch targets at least 44×44 pt. Respect safe areas (`react-native-safe-area-context`).
- Accessible labels on interactive elements; text must stay readable with larger system font sizes (cap `maxFontSizeMultiplier` only on labels inside instruments). Respect reduced motion.
- Provide loading, empty and error states for every screen that loads data.
- Animations run on the UI thread via Reanimated shared values, never React state per frame.
